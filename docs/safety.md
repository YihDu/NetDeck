# Safety and privacy — 0.2

- Profiles require explicit enablement before active checks; historical addresses are never scanned automatically. Unknown, disabled, blocked and stale are distinct from healthy. Current result signatures must match current Profile values.
- Frontend commands are typed and validated again in Rust. Network changes require a one-use five-minute preview token; frozen parameters and state-generation checks prevent silent post-preview substitution.
- System changes persist a before-snapshot first, execute fixed commands, read back, and attempt restoration on failure. Rollback requires the current state to match the recorded after-state. Stored rollback commands are revalidated against a fixed allow-list.
- SSH config includes are canonicalized and bounded. Read-only diagnosis rejects executable Match clauses. Explicit controlled sessions disable their entire condition blocks, disclose this in preview, and use a private frozen file. Custom forwarding strips all config forward directives; reuse mode refuses unsupported or non-loopback rules.
- NetDeck never reads private-key contents. OpenSSH may use existing identities / agent after confirmation. Host-key verification is strict, no agent forwarding, no hidden new host acceptance. Existing ProxyCommand/ProxyJump is disclosed before execution.
- Only fresh process groups created by NetDeck are signaled. No process-name termination or management of external SSH sessions. Normal exit waits for own SSH children and gateway connections to close.
- Gateway listens only on IPv4 loopback, caps clients/headers/setup/session duration, implements explicit HTTP and SOCKS5 upstream behavior, and never falls back to direct. No upstream credentials or PAC execution. Regular health checks do not switch upstream automatically.
- Reports are local, redacted and bounded; addresses remain for troubleshooting. Config and recovery snapshots use private temporary files and atomic replacement. No account, telemetry, upload or credential store.
- Development tests use loopback fixtures or mocked native IPC. No actual Tailscale toggles, system proxy writes, SSH authentication or remote curl were performed during implementation. Browser fixtures are marked Mock. Native window visual automation remains unavailable; no bypass was attempted.
- An operating-system setting change is not transactionally atomic with a local journal. Unexpected process termination can require manual reconciliation; the UI refuses an unsafe blind rollback. No guarantee that remote sshd policy preserves the requested bind address is made.
